## 질문: 테이블을 어떻게 들고 다닐 것인가

실제 모터 보드에 넣을 데이터 테이블을 만드는 단계에서 두 가지 방식이 떠올랐다.

- **A. 종류별 일반화 테이블 하나.** 모든 솔레노이드에 같은 표를 쓴다.
- **B. 부팅 시 1회 측정으로 개체를 분류하고, 등급별 테이블에서 고른다.**

B가 더 정밀해 보인다. 그런데 [4편](/posts/solenoid/04-incoming-lcr-automation/)의 전수 측정 수치를 놓고 보면 그렇지 않다.

| 요인 (잠금 L 기준)                                 | BIG      | SMALL     |
| -------------------------------------------------- | -------- | --------- |
| 개체 편차 (±3σ, 전수 측정)                         | ±1.6%    | ±3.7%     |
| 온도 0 → 80 °C                                     | 약 20%   | 약 20%    |
| 보드 리플 측정 오차 (예상: ADC, PWM 타이밍, V_bus) | ±3~5%    | ±3~5%     |
| 위치 잠금 → 해제                                   | **+95%** | **+164%** |

개체 차이가 온도 효과와 측정 오차보다 작다. **부팅 1회 측정으로 개체를 등급 분류하면, 개체가 아니라 그날 온도와 측정 잡음으로 나뉘게 된다.** 반면 위치 차이는 나머지를 다 합친 것보다 훨씬 크다. 그러니 종류별 한 기준으로 잠금/해제 판별이 된다.

## 결정: 종류별 테이블 하나 + 부팅 기준값 + 비율

**종류(BIG/SMALL)별 일반화 테이블 1개를 펌웨어 상수로 두고, 부팅 때 그 개체의 기준값(L_boot, R_boot)을 측정해서 모든 판정을 비율(L/L_boot, R/R_boot)로 한다.** 개체를 등급으로 나누는 방식은 쓰지 않는다. 이 결정은 1편에서 "보드 측정 게인 오차를 상쇄하려면 R/R_boot 비율을 쓰자"고 했던 아이디어를 L까지 확장한 것이다.

### 부팅 측정

- 무전원 잠금 상태에서 플런저가 움직이지 않는 약한 PWM(기동 전류의 30% 이하)을 짧게 걸어 R_boot, L_boot를 잰다.
- 용도는 세 가지. 개체 기준값, **종류 자동 판별**(BIG 8.8 mH·11.9 Ω / SMALL 3.3 mH·17.0 Ω), **단선·단락·오장착 검출**(정상 범위 밖이면).
- 비율로 판정하면 개체 편차와 **보드마다 다른 측정 게인 오차(션트, ADC)**가 함께 상쇄된다. 공장 LCR 값을 펌웨어에 넣는 것보다 나은 이유는, 보드가 보는 것이 동작 전류에서의 L이지 소신호 L이 아니기 때문이다.
- 첫 부팅 값을 EEPROM에 남기면 마모·걸림 추세를 볼 수 있다(선택).
- 예외 처리. L_boot가 잠금 범위보다 크면 플런저가 홈 위에 얹혔거나 복귀 실패다. 경고하고 기준은 공칭값으로 대체한다. 뜨거운 상태에서 재부팅하면 R_boot가 실온 값이 아니므로 절대 온도는 공칭 R₂₅로 계산한다(개체 편차 0.5% → 약 ±1~4 °C 오차).

### 종류별 고정 테이블 (펌웨어 상수)

| 항목      | 내용                                                                                                                                                     |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 위치 판별 | L/L_boot 기준선. 잠금 ≈ 1.0, 해제 BIG ≈ 1.95 / SMALL ≈ 2.64 → 기준선 예 BIG 1.4, SMALL 1.6. 중간 걸림 구간 추가                                          |
| 온도      | 구리 α 0.00393(검증 완료), 공칭 R₂₅(BIG 11.93 Ω, SMALL 16.98 Ω), L 온도계수로 기준선 보정                                                                |
| 구동      | I_hit = 최악 개체 기동 전류 × 1.5, I_hold = 최악 개체 유지 전류(진동 포함) × 1.5. 전압 구동이면 `Duty = I × R(측정값) / V_bus`. 부스트 전압·최대 ON 시간 |
| 열 한계   | 권선 100 °C 기준 R/R_boot 한계, 연속 전력 한계, 부스트 반복 간격                                                                                         |
| 정상 범위 | L_boot·R_boot 허용 범위(공칭 ± 온도 범위 ± 개체 편차) → 밖이면 단선·단락·오장착                                                                          |

### 동작 순서

부팅 측정 → 종류 판별·범위 확인 → Hit → Hold → 정해진 시간 안에 L/L_boot가 해제 기준을 넘는지 확인 → 실패하면 부스트 재시도 → 그래도 실패하면 모터 금지. 운전 중에는 R/R_boot로 권선 온도, L/L_boot로 위치를 계속 감시한다.

### 등급 방식을 도입할 조건

선정 개체의 정규화 곡선(L/L_boot의 위치·전류·온도별 변화)이 개체마다 겹치지 않고, 그 차이를 L_boot·R_boot가 예측할 때만 도입한다. 현재 단서는 SMALL의 잠금 L과 L비의 상관(r = −0.77)뿐이고 판별 여유가 커서 지금은 불필요하다.

## 측정 방식도 다시 정의했다

이 결정을 하고 나니 필요한 데이터가 분명해졌다. **온도에 따른 L_low, L_high, DCR 세 가지.** Q는 펌웨어가 쓰지 않으므로 더 이상 받지 않는다.

그런데 이걸 재는 방법이 두 가지다. "100 °C까지 데워 놓고 식히면서 L·DCR을 찍는 것"과 "전압을 단계별로 올려 정상상태를 만들고 찍는 것"은 같은가? 다르다.

- **냉각(무전원)**은 L(T)와 DCR(T) 곡선을 준다. L은 LCR로만 잴 수 있고 LCR은 무전원에서만 물릴 수 있으니, L의 온도 특성은 이 방법뿐이다.
- **정상상태(통전)**는 `V/I`와 열저항을 준다. 보드가 실제로 보는 것은 이쪽이다.

그래서 표를 둘로 나눴다.

1. **열평형 표**: 전압을 올릴 때마다 정상상태에서 V·A와 온도 → V/I(전원 인가 중 권선 저항), 전력, 열저항
2. **L·DCR 표**: 전원을 끈 채 식히며 잰 L·DCR. 잠금(L_low)과 해제(L_high)를 냉각 한 번씩

한 행에 V·I와 L·DCR을 같이 적던 예전 파일은 처음 실행할 때 자동으로 두 표로 나뉘도록 했다.

## 웹 도구: 정상상태 판정과 냉각 자동 기록

이전의 tkinter GUI 대신 **표준 라이브러리만 쓰는 로컬 웹 서버**(`http://127.0.0.1:8765`)로 다시 만들었다. 설치할 게 없고, 같은 네트워크의 태블릿에서도 열리고, 입력하면 그래프가 바로 갱신된다. 화면은 HTML·CSS·JS 직접 작성, 외부 라이브러리 없음.

### 입력 공통

- 개체 번호를 넣으면 그 개체의 입고 측정값(실온)과 선정 이유가 옆에 뜬다. 4편의 통계 폴더를 읽는다.
- 저장은 종류별 CSV. 엑셀로 열어 고쳐도 되고, 프로그램이 모르는 열은 보존한다. 엑셀이 파일을 잡고 있으면 저장이 거부되고 화면에 안내가 뜬다. 지우기·수정 직전 파일은 `.bak`으로 남는다.
- 경고(저장은 막지 않음): 입고 평균 대비 ±30% 초과(DCR·V/I는 온도 환산), 단위 실수(×1000), L_high < L_low, L비가 입고 평균과 15% 넘게 다를 때, 정상상태가 되기 전에 고정된 온도.

### 정상상태 판정 (열평형 모드)

온도계를 연결하면 켜진 채널의 실시간 그래프(최근 10/30/60분)가 뜨고, **켜진 채널 모두 최근 N분 동안 변화가 X °C 이하이면 정상상태**로 본다(기본 5분, 0.5 °C). 변화는 10초 평균값들의 최대 − 최소. 구간에 끊긴 곳이 있으면 처음부터 다시 세고, 프로브가 빠진 채널은 판정에서 뺀다. 조건이 맞으면 위쪽에 초록색 "지금 기록하세요"가 뜨고 탭 제목에 ✓가 붙는다. '이 온도로 기록 시작'을 누르면 켜진 채널들을 판정 구간 평균으로 고정하고 전압 칸으로 간다. V·A 칸에 값을 넣기 시작해도 온도가 고정된다.

판정 기준은 처음에 "일정 시간 동안 온도 변화가 얼마 이하"로 정했고, 숫자는 화면에서 바꾸면 저장된다. 한 개체에 열전대를 하나만 붙일 생각이었는데 T2도 쓰게 되어 채널 켜고 끄기를 넣었다.

### 냉각 자동 기록 (L·DCR 모드)

LCR 미터와 온도계를 둘 다 연결하면 **서버가** 기록한다.

1. 데운 뒤 전원을 끄고 LCR 클립을 물린다. 플런저를 잠금(또는 해제) 위치에 둔다.
2. 위치를 고르고 '냉각 기록 시작'. 간격(기본 5초)마다 Ls·Rdc를 안정 판독(연속 3회 ±0.3%)으로 읽고, **온도가 0.3 °C 이상 변했을 때만 저장**한다. 실온 근처의 느린 꼬리가 표를 넘치게 하지 않도록.
3. 멈춤 온도(기본 35 °C)에 닿거나, 정지를 누르거나, 클립이 빠져 OPEN이 3번 연속 나오면 멈춘다.
4. 다시 데운 뒤 반대 위치로 한 번 더.

브라우저 탭을 다른 곳으로 옮겨도 계속된다. 기록은 왼쪽 목록에 한 줄씩(번호·개체·위치·온도 범위·점 수) 나온다.

L비는 L_high 점마다 **같은 온도의 L_low 곡선(잠금 기록)을 보간**해서 나눈다. 두 위치를 따로 식히니 같은 온도에 두 값이 직접 있지 않기 때문이다. 1 °C 구간 평균으로 곡선을 만들고 외삽은 하지 않는다.

### 실수를 되돌릴 수 있게

첫날 냉각 기록을 45번 개체로 해야 하는데 47번으로 저장했다. 지우고 다시 재기엔 한 번에 수십 분이 걸린다. 그래서 그 줄의 '번호 변경'으로 **기록 전체의 번호를 바꾸는** 기능을 넣었다(기록 중에도 가능, 직전 파일은 `.bak`). 그리고 개체 번호와 기록 채널이 지금까지의 기록과 다르면(예: 주로 T2로 잰 #47을 T1으로) 시작 전에 경고하고 한 번 더 묻게 했다. 잘못된 데이터는 지우는 것보다 바로잡을 수 있어야 한다.

그래프는 범례를 눌러 개체를 숨기고, 마우스로 상자를 그려 확대하고, 더블클릭으로 되돌린다. '크게' 버튼은 화면 가득 띄운다. 그래프 종류는 L_low·L_high·L비 대 온도(개체별 직선 적합), 저항 대 온도(채운 점 = DCR, 속 빈 점 = V/I), L/L_boot와 R/R_boot(구리 이론선 포함), 정상상태 온도 대 전력(기울기 = 열저항), 저항법 온도 오차, L 온도계수 분포.

### 표

- 개체별 25 °C 값과 %/°C
- 개체별 정상상태 전력: 열저항, P=0 외삽 온도(≈ 주변), V/I@25 °C
- **펌웨어 테이블 초안**: 온도 구간별 V·A·P·V/I, L/L_boot 범위, 판별 여유, 중간값. 부팅 기준 = 각 개체의 가장 낮은 온도 측정

## 이날의 첫 데이터

BIG 두 개체를 브라켓에 달고 3 → 4 → 5 V로 올렸다. 3 V(0.22 A, 0.67 W)에서는 44 °C로 정상상태에 들었고, 4 V와 5 V는 아직 오르는 중에 기록했다(5 V, 1.65 W에서 프로브 72 °C). 그리고 밤에 첫 냉각 기록 두 번. 이 데이터를 이틀 뒤 들여다보다 측정 오차 세 가지를 찾게 된다. [6편](/posts/solenoid/06-error-correction-and-board-curves/)에서 계속.
